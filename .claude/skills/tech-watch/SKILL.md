# Technical watch

Method, sources and closing rules: `tech-watch/README.md` (follow it exactly).

1. Record the commit, the cutoff date and the pinned versions you inspected.
2. Form findings from the code before reading `tech-watch/pending/`.
3. Search primary sources, newest first; open the original behind every post; record dates and depth.
4. One decision per idea: adopt, evaluate, retain, defer, reject — with local fit and the smallest experiment.
5. Write `tech-watch/pending/YYYY-MM-DD-<topic>/index.md`; open one pull request; skill `pr-review`.
"Nothing worth changing" is a valid result: then no package.

## Separate source activity from a reason to adopt
A new tag, star count or longer checklist is not evidence of local task quality. Compare the
actual source delta with a demonstrated project gap; retain the current implementation when
no distinct benefit survives. For skill maintenance, only the four lifecycle-approved sources
are inputs. Record adopted technique, rejected obligations and a realistic validation case;
do not inherit model choices, mandatory agent fleets or universal numeric quality thresholds.
