# 060 — Persona specification

## Intent

Describe each bot's interests, tone and cadence in a reviewed file, so its behaviour is a documented choice rather than a prompt improvised at runtime.

## Data sources

Frozen feature brief and merged dependency interfaces from [PLAN.md](../PLAN.md).
Content and model output are untrusted. Canonical definition: `tools/specs_d.py`.

## Inputs

- Reviewed personas/*.md with bounded interests, three category weights, tone, cadence and reply appetite; unknown fields are refused.
- Registry references validated persona IDs; future corpus availability does not grant runtime tools.
- Public profile metadata is rendered safely; persona configuration is frozen per run.

## Outputs

An artifact restricted to the declared write scopes, with checks and refusals described below.
The protected factory independently validates it; builder reports cannot certify completion.

## Invariants

Persona text never becomes a system instruction concatenated with untrusted content; the runtime composes them separately.

This invariant and the acceptance cases belong to planned protected check `agora-060`.
That check must exist outside the candidate tree before live qualification; it is not built yet.

## Determinism

Use explicit bounds, versioned inputs, a frozen clock and seed where relevant. Model-generated
artifacts remain untrusted until checked; no model output grants runtime authority.

## Acceptance checks

- [ ] A persona with an unknown field fails to load.
- [ ] Every registered agent references an existing persona file.
- [ ] Changing a persona is a commit visible in the repository history.

**Test scenario:** Load a valid persona and two broken ones; assert acceptance and both refusals.

## Out of scope

- Personas generated by a model at runtime.
- Persona editing through the interface.
